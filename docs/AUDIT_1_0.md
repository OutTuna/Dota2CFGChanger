# Dota2CFGChanger — аудит готовности 1.0

Дата: 21 октября 2026. Исходная ревизия: `ca72461b70679fdb18651869a150db4af2f34142`.
Рабочая ветка: `alpha`. Изменения main и других веток, ручное изменение номера
стабильной версии и публикация стабильного релиза не выполнялись. По отдельному
запросу разрешён push alpha для Windows/Linux CI и изолированного prerelease.

## 1. Audit Summary

Проверены CMake, README/TODO, оба исходных workflow, Steam discovery/profile parsing,
копирование/бэкапы/восстановление, file worker и shutdown, обновление и helper,
локализация, ImGui layout, события GLFW, аватары и OpenGL lifetime.

Уже существовали: транзакционная замена каталога с откатом, проверяемые SHA-256
бэкапы с историей из пяти копий, фоновый файловый worker, координация запросов
профилей, пул аватаров до восьми потоков, event-driven рендер, остановка и join
потоков до удаления GLFW, проверка размера/хеша обновлений и откат при неудачном
запуске. Эти механизмы сохранены.

## 2. Critical Fixes

- Проверка подготовленной копии и повторная проверка обычных изменений источника и назначения.
- Межпроцессная блокировка destination, отсутствие второго бэкапа/записи при занятом аккаунте.
- Сохранение lock после принудительного завершения процесса; никакого автоматического удаления по таймауту.
- Проверка свободного места до staging/backup. Это advisory check: отказ реальной записи по-прежнему обрабатывается откатом.
- Проверка ссылок/reparse/special entries до операций, включая account parent и backup metadata.
- Ограничение и проверка загрузок обновлений, HTTPS-only redirects, явная certificate verification, отказ от prerelease.

Fault injection покрывает повреждённую копию, изменение источника/назначения при копировании,
недостаток места, ошибки copy/rename/cleanup, успешный и неуспешный откат, сохранение
recovery data. Реальные Steam/Dota-конфиги не изменялись.

Блокировка не запрещает Steam или другому процессу менять файлы. Проверки по путям
не дают полной защиты от враждебной замены компонентов между системными вызовами.
Проверка metadata не является атомарным snapshot и не обнаруживает любой случай
специально сохранённых размеров/mtime. Steam/Dota необходимо закрывать.

## 3. New Features

Реализованы фоновый предпросмотр полного `570`, действия Add/Replace/Unchanged/Remove,
число затронутых файлов и объём копирования; проверка плана перед применением;
пропуск идентичных переносов без записи/бэкапов. Отмена инвалидирует поздний результат
worker и освобождает данные предпросмотра.

В UX добавлены поиск по имени/ID, контекстное открытие папки аккаунта, clipping больших
списков и клавиатурная навигация. Layout проверяется без GPU с 10 000 аккаунтов и
10 000 preview entries на EN/RU/UA.

Выборочный перенос отложен: репозиторий не подтверждает зависимости реальных конфигов
Dota 2. Вымышленные категории или произвольное смешивание связанных файлов не добавлены.
Текстовый diff, импорт/экспорт, pin бэкапов и автоматическая диагностика не добавлялись:
для текущего полного переноса они увеличивают объём проверки и интерфейс без доказанной
необходимости. High-DPI требует проверки на целевых ОС.

Alpha CI использует уникальные теги `alpha-vX.Y-<run-id>-<attempt>`, `--prerelease` и
`--latest=false`; не создаёт стабильных `vX.Y` тегов и не удаляет/перемещает `latest`.
Канал виден в заголовке/Info. Сравнение версий остаётся числовым. Stable updater
обращается только к `latest` и дополнительно отвергает prerelease. Скрипт публикации
тестируется с fake `gh`, включая отказ для main/stable/beta и некорректных входов.

## 4. Performance

Воспроизводимая синтетическая фикстура: 128 × 4096 байт, семь переносов в каждом
сценарии, median, тёплый filesystem cache, AppleClang 17 / arm64, `-O2`. Сравниваются
исходные core-файлы из указанной Git-ревизии и рабочие файлы. Бенчмарк использует
временные каталоги. Полные числа: [AUDIT_METRICS.json](AUDIT_METRICS.json).

| Показатель | До | После | Границы результата |
| --- | ---: | ---: | --- |
| Идентичный перенос, median | 48.376 ms | 9.461 ms | Около 5.1× быстрее; нет записи/бэкапа. |
| Изменённый перенос, median | 52.430 ms | 73.565 ms | Около 40% медленнее: дополнительные проверки сохранности. |
| CPU time процесса benchmark, user + system | 0.765 s | 0.626 s | Суммарно фикстуры и оба сценария, не CPU% GUI. |
| Peak RSS процесса benchmark | 4 898 816 B | 4 456 448 B | Один небольшой core-процесс, не RAM приложения с GUI. |
| CPU/RAM/GPU живого приложения | не измерено | не измерено | Нет целевого Windows/Linux runtime на этом Mac. |
| Startup / Steam account scan | не измерено | не измерено | Полноценный целевой runtime не проверен. |

драйвера. LTO, агрессивные compiler flags и новые зависимости приложения не добавлялись.

## 5. Testing

До push пройдены:

- Чистая локальная Release-сборка и 12/12 CTest на Mac; portable и process-integration labels.
- 12/12 CTest с AddressSanitizer + UndefinedBehaviorSanitizer; инструментированы также оба бинарника fault-injection/settings из `core_checks.py`.
- Расширенный `core_checks.py`, все локали, 4 AppImage ABI unit tests, AUR source-guard regression.
- Шесть version-logic сценариев, игнорирующих alpha/beta tags, и отдельная проверка изоляции prerelease publication.
- `actionlint` для workflow; проверка актуальности AUR patch, его применение к чистому v1.22 и побайтовое совпадение ожидаемых исходников.
- Полная кросс-компиляция Windows EXE и 12 test EXE через MinGW; выполнение Windows EXE не проверялось.

На Mac полная GUI-компиляция использовала только локальный include alias
`GL/gl.h` → `OpenGL/gl.h`, не включённый в репозиторий. Для portable test targets
этот alias не требуется. Для curl использован native macOS TLS; старый bundled curl
с установленным OpenSSL 4 не собирался. В Windows cross-сборке локально выключен
HTTP/2, чтобы не линковать найденный на host arm64 nghttp2. Это ограничения локального
окружения, а не изменения Windows/Linux release options.

GitHub CI alpha проверяет штатные Windows/Linux toolchain и AppImage. Его результаты
нужно смотреть по актуальному alpha commit; локальные результаты не подменяют CI.
Отдельный sanitizer workflow также запускается для alpha.

Не проверены здесь: NTFS junction/reparse runtime, реальные locked files/ACL,
завершение процесса на каждом промежуточном шаге commit/update, физический отказ диска,
power-loss durability, полный HTTPS MITM/redirect integration, ручной GUI/DPI и
реальный игровой перенос. Network service tests используют mock transports.

## 6. Architecture

Сохранены C++17, Dear ImGui, GLFW, OpenGL и существующие модули. Добавлен небольшой
`config_preview` core-модуль и callback перед файловой заменой, чтобы бэкап и
валидация плана выполнялись под одной destination-блокировкой. Файловые callback
results и preview state применяются на UI thread. Новых сторонних runtime-зависимостей нет.

Стабильный release/Arch CI в других ветках не изменён. В alpha сохранены build/test jobs,
удалён stable publisher и добавлены isolated alpha publication и
sanitizer workflow. AUR patch — генерируемая совместимость с v1.22, поэтому его diff
больше изменения непосредственных исходников. Комментарии удалены из кода по запросу;
директивы, shebang, строки и документация сохранены. Co-Authored-By не добавляется.

## 8. Release Readiness

**NOT READY для стабильного 1.0.** Подтверждённые дефекты выше исправлены и локально
покрыты тестами, но критические целевые runtime/crash-сценарии и независимая модель
подлинности обновлений ещё не закрыты. Alpha предназначена для проверки CI и ручного
тестирования. Успешная сборка сама по себе не переводит проект в READY.
