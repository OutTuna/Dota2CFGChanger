# Arch Linux / AUR

Рецепт находится в `packaging/aur`. Пока это подготовка к публикации: команды `yay -S dota2cfgchanger` и `paru -S dota2cfgchanger` заработают после появления пакета в AUR.

## Что собирается

Пакет `dota2cfgchanger` для x86_64 собирается из исходников релиза v1.22. curl, GLFW, OpenSSL и JSON берутся из системных пакетов. cpr, ImGui и stb скачиваются как закреплённые архивы с SHA-256 до сборки. На этапе CMake и компиляции сеть не нужна.

В v1.22 ещё нет режима пакетной установки, поэтому рецепт применяет `packaging-support.patch`. Он добавляет установку файлов и отключает самостоятельную замену бинарника. Проверка новой версии остаётся, но программа предлагает обновить пакет через пакетный менеджер. После выхода релиза с этими изменениями нужно обновить `pkgver`, checksum исходников и убрать совместимый патч из рецепта.

Устанавливаются `/usr/bin/DotaManager`, desktop-файл, PNG-иконка и лицензии. Настройки, аватары и бэкапы остаются в пользовательском каталоге DotaManager. Удаление пакета их не удаляет.

## Проверка без своего Arch

Запушить ветку `aur-packaging` и открыть workflow **Arch package checks**. CI подготовит чистый контейнер Arch, проверит контрольные суммы и патч, затем в контейнере без сети:

1. Соберёт пакет и выполнит C++ и Python тесты.
2. Проверит пакет через namcap и установит его.
3. Проверит desktop-файл и открытие окна под Xvfb.
4. Удалит пакет и проверит сохранение пользовательских данных.

Готовый `.pkg.tar.zst`, рецепт и журнал namcap появятся в артефакте `dota2cfgchanger-arch`. Обычный Windows/AppImage workflow также работает на этой ветке, но публикация релизов разрешена только из `main`.

Контейнер проверяет сборку и запуск с программным OpenGL. Проверку реальных драйверов, файлового диалога и переноса конфига на пользовательском Arch он не заменяет.

## Сборка на Arch

```sh
sudo pacman -S --needed base-devel cmake ninja nlohmann-json python
cd packaging/aur
makepkg -si
```

`makepkg` запускается обычным пользователем. Он проверяет исходники, применяет патч, собирает приложение и запускает тесты. `-s` устанавливает зависимости, `-i` устанавливает готовый пакет.

## Обновление рецепта

После изменения файлов из `packaging/aur/source-files.txt` пересобрать патч относительно распакованного исходного релиза:

```sh
python3 scripts/refresh-aur-patch.py /path/to/Dota2CFGChanger-1.22
cd packaging/aur
makepkg --printsrcinfo | sed '/^#/d' > .SRCINFO
```

Скрипт обновляет и SHA-256 патча в PKGBUILD. `.SRCINFO` хранится без заголовка с датой, чтобы результат был воспроизводимым. При изменении рецепта без обновления версии приложения увеличивается `pkgrel`; при новом релизе меняется `pkgver`, `pkgrel` снова становится 1. Контрольные суммы нужно вычислять из реально скачанных архивов; `SKIP` здесь не используется.

## Публикация

После успешного CI понадобится аккаунт AUR и добавленный SSH-ключ. Перед первой публикацией проверить, что имя `dota2cfgchanger` свободно. AUR хранит рецепт, а исходники скачиваются с GitHub при сборке.

```sh
git clone ssh://aur@aur.archlinux.org/dota2cfgchanger.git
```

В отдельный AUR-репозиторий скопировать только `PKGBUILD`, `.SRCINFO` и `packaging-support.patch`, затем сделать обычный commit и push от своего имени. Архивы исходников, каталог сборки и готовый пакет туда не добавляются.

После публикации пользователи смогут установить пакет через `yay -S dota2cfgchanger` или `paru -S dota2cfgchanger`. Для обновления сопровождающий выпускает новую версию рецепта в AUR, а пользователь обновляет систему через `yay -Syu` или `paru -Syu`.
